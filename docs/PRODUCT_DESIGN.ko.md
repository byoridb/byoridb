# ByoriDB 제품 철학과 설계

> [English](PRODUCT_DESIGN.md) | **한국어**
>
> 방향 채택: 2026-10-30. 이 문서는 제품과 아키텍처의 목표를 정의합니다.
> 구현된 API나 출시 기능을 발표하는 문서가 아닙니다.

ByoriDB는 **에이전트를 주 사용자로 삼는 범용 그래프·온톨로지 데이터베이스**입니다.
에이전트가 관계를 조회하고, 명시적인 규칙을 적용하고, 도출 근거를 확인하며,
서버가 강제하는 계약 아래 공유 상태를 변경할 수 있게 합니다. 제품의 목표는
제한된 실행 예산 안에서 작업을 정확히 완료하고 상태의 일관성을 지키는 것입니다.
이는 평가할 목표이며, 이미 측정된 경쟁 우위를 주장하는 것이 아닙니다.

제품과 상호작용 설계의 기준은 이 문서입니다. [PLAN.ko.md](PLAN.ko.md)는
개발 순서, 작업 상태, 완료 근거, 출시 선행 조건의 기준입니다.
출시 기준선은 v0.4.20이며 이후 구현 상태는 개발 플랜에서 구분합니다.
계약이나 제품 결정을 바꿀 때는 한·영 문서를 함께 갱신합니다.

## 제품의 책임 범위

API의 주 사용자는 에이전트입니다. 사람은 데이터베이스를 운영하고, 권한을
부여하고, 관찰·감사·복구합니다. 이 책임을 수행할 CLI와 읽기 쉬운 문서도
필요합니다. 이들의 역할은 기계용 계약을 관찰하고 운영할 수 있게 하는 것이며,
별도의 동작 기준을 만드는 것이 아닙니다.

데이터베이스는 영속적인 사실·관계·스키마, 조회, 결정적인 규칙 실행, 도출 근거,
제약 조건, 데이터 접근 통제를 담당합니다. 애플리케이션은 모델 선택, 프롬프트,
작업 계획, 승인, 업무 행동, 외부 부수 효과를 담당합니다.
ByoriDB가 LLM 실행 환경이나 에이전트 작업 스케줄러가 되지는 않습니다.

에이전트 메모리는 엔진의 활용 사례 중 하나입니다. 의존성 분석, 변화하는 도메인
모델, 정책 평가, 운영 상태 공유도 활용 범위에 포함됩니다. 그래프·온톨로지 코어는
범용으로 유지합니다. 프로토콜 어댑터가 저장 모델을 결정하거나 데이터베이스를
사용하는 유일한 경로가 되지는 않습니다.

Rust 단일 노드 엔진과 redb 저장 기반을 유지합니다. HTTP/gRPC, 지원 클라이언트,
향후 어댑터는 실행·인가 의미를 공유해야 합니다. 분산 운영, RDF/SPARQL 호환,
대체 실행 엔진에는 개발 플랜의 진입 조건을 유지합니다. 이 방향 전환이 엔진의
전면 재작성을 승인하는 것은 아닙니다.

## 설계 원칙

1. **추측하기 전에 발견한다.** 에이전트는 접근 가능한 스키마, 값 타입,
   지원 연산, 제한 사항, 계약 버전을 확인할 수 있어야 합니다.
2. **의미를 기계가 판독할 수 있게 한다.** 타입 있는 값, 오류, 결과 완전성,
   쓰기 결과를 이해하기 위해 자연어 설명을 해석할 필요가 없어야 합니다.
3. **사실·도출·주장을 구분한다.** 명시 사실과 논리적 결과는 의미가 다르며,
   모델이 생성한 주장을 자동으로 참으로 취급하지 않습니다.
4. **누락을 숨기지 않으면서 작업량을 제한한다.** 예산·취소의 동작을 명시합니다.
   잘린 근거나 중단된 조회를 완전한 결과로 표시하지 않습니다.
5. **재시도와 동시 변경을 명시적으로 다룬다.** 영속적인 처리 결과, 멱등성,
   리비전 검사가 에이전트의 기억에 의존하지 않고 공유 상태를 보호합니다.
6. **권한은 서버가 강제한다.** 프롬프트, 도구 설명, 클라이언트 힌트,
   성공한 미리보기는 권한을 부여하지 않습니다.
7. **완료된 작업을 측정한다.** 호출·토큰·시간·인프라 절감을 주장하기 전에
   최종 답변과 데이터베이스 상태가 올바른지 평가합니다.

## 목표 에이전트 상호작용

목표 흐름은 다음과 같습니다.

**발견 → 조회 → 근거 확인 → 변경 준비 → 권한에 따른 적용 → 재확인.**

| 단계 | 에이전트가 받거나 제공하는 것 | 서버가 보장해야 할 동작 |
|---|---|---|
| 발견 | 허용된 스키마, 기능 계약 버전, 한도, 값·ID 타입 | 현재 권한에 따라 메타데이터를 걸러 내고 지원·미지원 동작을 표시 |
| 조회 | 타입 있는 연산 또는 매개변수화된 쿼리, 읽기 범위, 예산 | 권한과 한도를 강제하고 데이터 뷰와 결과 완전성을 식별 |
| 근거 확인 | 선택된 사실, 도출 참조, 출처 참조 | 각각의 의미를 유지하고 한도 내에서 이어 볼 수 있게 제공 |
| 변경 준비 | 변경 의도, 기대 리비전, 영향 확인 요청 | 선언된 범위에서 검증·미리보기하며 데이터 변경이나 권한 부여는 하지 않음 |
| 적용 | 변경 또는 유효한 준비 계획, 사전 조건, 멱등성 키 | 커밋 시 권한과 리비전을 재검사하고 명시적인 처리 결과 반환 |
| 재확인 | 처리 결과 조회와 허용된 상태 조회 | 불확실한 처리 결과를 확인하고 커밋된 상태를 의도한 변경과 비교 |

읽기 전용 작업은 근거 확인에서 끝납니다. 변경 준비가 모든 쓰기에 사람의 확인을
요구하는 것은 아닙니다. 승인 정책은 호출 애플리케이션이 결정합니다. 호출자가
에이전트·사람·자동화 작업 중 누구인지와 관계없이 데이터베이스는 적용에 필요한
권한과 사전 조건을 강제합니다.

아래의 연산 명칭과 필드는 **제안하는 계약**입니다.
실행 가능한 엔드포인트, 현재 SDK 메서드, 이미 존재하는 MCP 서버가 아닙니다.
실제 전송 계층 명칭과 데이터 스키마는 각 구현 작업에서 확정합니다.

## 기계용 계약

### 기능 발견과 값 — AGT-1, API-1, API-2

발견 응답은 선택한 스페이스, 스키마 버전, 접근 가능한 태그·간선 타입,
속성 타입, 외부 정점 ID 타입, 지원 연산, 관련 한도를 알려야 합니다.
권한은 인증된 주체와 스페이스 범위로 표현합니다. 기능 응답은 현재 사용 가능
상태를 설명할 뿐 양도 가능한 인가 토큰이 아니며, 후속 호출에서도 인가합니다.

접근할 수 없는 스키마, 스페이스 이름, 개수, 예시, 기능을 응답으로 노출하지
않습니다. 미지원 동작과 현재 주체에게 허용되지 않은 동작은 일관된 공개 정책으로
다루어야 하며, 오류 메시지가 접근 제한 정보를 누출해서는 안 됩니다.

INT64 ID, 리비전, 타임스탬프, 카운터를 JSON 숫자 정밀도 손실 없이 표현합니다.
타입 태그 또는 문자열 기반 인코딩을 정의하고 JSON·protobuf·SDK 왕복을 검증합니다.
문자열 `"42"`와 정수 `42`를 구분하며 문자열 ID의 내부 매핑 대신 외부 ID를
노출합니다. null, 없는 속성, 빈 컬렉션, 타입 있는 복합 값을 구분합니다.

타입 있는 매개변수 바인딩과 구조화된 연산을 공통 검증·실행 경로에 추가합니다.
어댑터가 입력을 쿼리 문자열에 끼워 넣는 방식으로 구현하지 않습니다.
텍스트 쿼리 API는 호환성 정책과 함께 유지합니다. 고급 호출자도 같은 인가·결과
계약을 거쳐 사용해야 합니다.

### 결과·근거·불확실성 — AGT-2

결과 응답에는 계약 버전, 요청 참조, 선택한 스페이스, 데이터 뷰 참조,
타입 있는 데이터, 실행 상태, 완전성 정보가 필요합니다. 중복 열 이름이 값을
덮어쓰지 않도록 순서 있는 열 설명과 위치 기반 행 또는 동등하게 손실 없는
형태를 사용합니다. 비유한 수를 포함해 지원하는 모든 값의 JSON·protobuf 표현이
동등하도록 정의합니다. 쿼리 결과의 완전성과
근거 표시의 완전성을 구분합니다. 답변이 완전해도 설명은 제한될 수 있지만,
그 제한은 드러나야 합니다.

사용자가 지정한 `LIMIT`은 쿼리 결과의 의미를 정의합니다. 숨겨진 스캔 한도,
시간 초과, 파티션 실패는 그렇지 않습니다. 기본 계약은 쿼리가 정의한 완전한
결과 또는 명시적인 오류입니다. 향후 부분 결과 모드는 명시적인 선택, 기계가
판독할 수 있는 사유, 완전한 답으로 취급해서는 안 된다는 계약이 필요합니다.

근거는 항목 수, 바이트 수, 탐색·도출 깊이, 실행 시간으로 제한합니다.
전체 추론 폐쇄를 무제한 반환하지 않고 선택된 전제·규칙 참조와 이어 보기 수단을
제공합니다. 도달한 한도와 평가하지 못한 범위를 표시합니다. 참조 중복을 제거할
때도 다른 도출 경로를 설명 없이 없애지 않습니다.

커서는 주체, 스페이스, 연산·매개변수, 정렬, 데이터 뷰에 묶고 불투명하거나
무결성 보호가 된 형태로 제공하며 수명을 명시합니다. 스냅샷 보존과 변경·권한 회수·
재시작·만료 시 동작을 정의합니다. 다른 뷰에서 조용히 이어 읽지 않습니다.
스냅샷 이어 읽기를 구현하기 전에는 안정적인 페이지 스냅샷을 약속하지 않고
해당 기능을 미지원으로 응답합니다.

일치하는 명시 사실, 도출된 사실, 모델이 지원하는 명시적 부정, 알 수 없거나
평가하지 않은 명제를 별도 의미 상태로 표현합니다. 일치 행이 없다는 것은
선언한 뷰와 조회 범위에서 일치가 없다는 뜻이며 보편적인 거짓을 뜻하지 않습니다.
불완전한 평가로 부재를 확정할 수 없습니다. 지원하는 연산별로 적용되는
개방 세계·폐쇄 세계 가정을 정의합니다.

### 명시 사실의 출처와 규칙 전제 자격 — SEM-8

논리적 도출 근거는 어떤 사실과 규칙에서 결과가 나왔는지 기록합니다. 출처 이력은
명시 사실이 어디서 왔고 어떻게 적재·변경됐는지 기록합니다. 도출 가능성의 증명은
입력 사실이 현실을 정확히 기술한다는 증명이 아닙니다. LLM이 생성한 주장은
생성 출처와 인식 상태를 명시해야 합니다. 주장을 데이터로 저장했다고 해서
모든 규칙 집합에서 신뢰하는 전제로 자동 승격하지 않습니다.

SEM-8은 출처·수집 metadata와 규칙 전제 자격 정책을 정의하며 출처 누락과 기존
명시 사실의 이관도 포함합니다. 구조화 연산·텍스트·bulk write 경로에 같은 정책을
강제하고 복구 뒤에도 이를 보존합니다.

### 오류·재시도·쓰기 처리 결과 — API-2, AGT-3

잘못된 요청, 미지원 기능, 인증 실패, 권한 부족, 충돌, 자원 부족, 만료된 뷰·계획,
내부·저장소 실패, 처리 결과 불확실성을 안정적인 오류 분류와 구조화된 문맥으로
반환합니다. 자연어 메시지는 운영자를 돕지만 재시도 프로토콜이 되지 않습니다.

재시도 가능한 오류인지와 변경이 적용됐는지를 구분합니다. 쓰기는 해당하는 경우
미적용 확정, 커밋 완료, 부분 적용, 알 수 없음으로 결과를 표현합니다. 원자적 배치
구현 전에는 복합 실행의 앞부분이 이미 커밋됐을 수 있습니다. 알 수 있다면 실패한
문장과 커밋된 앞부분을 포함하며, 일반 실행 오류를 롤백으로 표현하지 않습니다.

멱등성 기록은 키를 인증된 주체, 스페이스, 연산, 정규화된 요청 해시,
영속 처리 결과에 묶습니다. 동시에 도착한 중복 요청은 같은 기록을 통해 조정합니다.
같은 키에 다른 요청 내용이 들어오면 거절합니다. 완료된 요청을 반복하면 현재의
접근 권한을 확인한 뒤 기록된 결과를 반환하고 변경을 다시 실행하지 않습니다.

지원하는 트랜잭션 경계는 상태 변경과 처리 결과 기록을 원자적으로 묶어야 합니다.
지원하는 이력·인덱스·카운터·추론 효과도 그 경계에 포함합니다.
원자적 KV 배치만으로 전체 연산의 원자성이 성립하지는 않습니다.
미지원 연산은 보호되는 것처럼 보이게 하지 말고 변경 전에 멱등성 사용을 거절합니다.
복구 시 장애로 남은 진행 중 기록을 해소해야 합니다. AGT-3 출시 전에 정규화 방식,
최대 키·요청 크기, 할당량, 보존 기간, 만료 동작, 중복 방지의 정확한 보장 범위를
정의합니다. 무제한 또는 외부 시스템까지 포함한 정확히 한 번 실행을 약속하지 않습니다.

전송 시간 초과나 연결 종료 뒤에도 서버는 이미 커밋했을 수 있습니다. 호출자는
재시도를 결정하기 전에 원래 연산 참조·키로 영속 처리 결과를 조회합니다.
취소는 어느 지점에서 작업이 멈추고 어떤 커밋이 이미 발생했을 수 있는지 정의합니다.
이미 커밋된 쓰기를 되돌리는 기능은 아닙니다.

### 동시 변경과 준비 — AGT-4

변경은 정의된 범위의 기대 데이터 리비전과 스키마 버전을 지원합니다.
구현 시 스페이스 전체 또는 엔티티별 충돌 감지 중 방식을 선택하고 문서화해야 합니다.
오래된 사전 조건은 지원하는 원자적 경계 안에서 변경 없이 충돌로 실패합니다.
지원하지 않는 사전 조건은 명시적으로 거절합니다.

준비된 변경은 의도한 효과, 영향 범위, 가정, 기대 리비전, 스키마 버전, 만료 시점을
설명합니다. 서버는 이를 주체, 스페이스, 요청, 계획 버전에 묶습니다. 미리보기는
예약도 권한 부여도 아닙니다. 미리보기·적용 과정에서 검증과 커밋 사이의 경쟁 조건을
숨기지 않습니다.

적용은 커밋 경계에서 권한, 스키마, 리비전, 계획 유효 기간을 다시 검사합니다.
만료되거나 오래된 계획은 다시 계산하고, 애플리케이션 정책상 필요하면 다시 승인받습니다.
과거 승인 아래 다른 계획을 조용히 적용하지 않습니다. 애플리케이션 승인과 업무상
외부 부수 효과 실행은 엔진 밖의 책임이며, 그 기록에서 영속 DB 연산을 참조할 수 있습니다.

현재 되돌릴 수 없는 `sameAs` 병합을 에이전트가 안전하게 준비할 수 있는 동작으로
제공하려면 영향·충돌 확인과 병합 기록 보존이 먼저 필요합니다.
미리보기가 되돌리기를 구현해 주지는 않습니다. 병합된 정체성을 나누는 기능은
별도의 데이터 보존 설계가 필요하며 미리보기 적용을 단순히 역으로 실행하는 것이 아닙니다.

## 권한·신뢰할 수 없는 데이터·운영

영속적인 스페이스별 권한과 직접·복합·프로파일·발견·근거·관리 경로의 일관된
검사를 통해 최소 권한을 강제합니다. 읽기 전용 요청 제한은 쓰기 가능한 세션의
해당 요청 권한을 줄일 수 있지만 늘릴 수는 없습니다. 권한 회수는 후속 실행에
반영해야 하며 준비된 변경을 커밋하기 전에 다시 확인해야 합니다.

조회된 텍스트, 속성, 원본 문서, 주장 내용은 도구 지시처럼 보이더라도 데이터로
취급합니다. 구조화된 응답은 데이터 내용과 신뢰하는 프로토콜 제어 필드를 구분합니다.
도구 주석과 어댑터 프롬프트는 사용을 돕는 힌트이며 권한 강제 수단이 아닙니다.
엔진이 모든 모델 수준 프롬프트 주입을 막을 수는 없지만, 데이터가 DB 권한을
부여하는 것은 막아야 합니다.

자격 증명, 세션 토큰, 민감한 그래프 값이 기능 발견·추적·픽스처·메트릭·평가 산출물로
누출되지 않게 합니다. 사람의 운영에는 권한 있는 감사 참조, 내용까지 확인하는
백업 검증, 복구 훈련, 저장 형식 버전 정책, 지원하는 보안 배포 구성이 필요합니다.
DEP-1 의존성 감사는 계속 출시 준비 요건이며, 현재 자동 릴리스 경로의
강제 검증 공백은 PLAN에 기록합니다.

## 아키텍처와 전환

| 계층 | 이 설계에서의 책임 |
|---|---|
| `byoridb-graph` | 공통 GraphService 경계, 인증된 발견·연산, 요청 한도, 프로토콜 변환, 처리 결과 관리 |
| `byoridb-common` | 공통 타입 있는 값과 안정적인 계약·오류 정의, 명시적인 전송 변환 규칙 |
| `byoridb-parser` | 기존 텍스트 구문과 타입 있는 매개변수 구문, 독립적인 권한 판단 금지 |
| `byoridb-executor` | 조회 완전성, 규칙·제약 의미, 근거 선택, 지원하는 변경 동작 |
| `byoridb-storage`, `byoridb-kvstore` | 원자적 영속화 경계, 리비전·처리 결과 영속성, 이력, 백업·복구 |
| `byoridb-client` | 호환되는 타입 있는 전송 바인딩과 클라이언트용 처리 결과, 서버가 최종 권한 결정 |
| `byoridb-bulkloader` | 일반 쓰기와 의미 동등성 또는 명시적 재구축·검증 모드, 숨겨진 의미 우회 금지 |
| 필요 시 `byori`를 포함한 외부 어댑터 | 프로토콜 도구를 지원 계약에 매핑하고 권한·타입·한도·처리 결과·호환성 유지 |

이 표는 책임 배치이며 목표 계약이 구현됐다는 주장이 아닙니다.
현재 HTTP/gRPC 서비스, 기본 protobuf 결과 타입, 요청별 `read_only` 검사는 활용할
기반입니다. `SHOW`/`DESCRIBE`로 쿼리 기반 발견은 이미 가능하며, 버전이 있는 전용
기능 명세는 새 작업입니다. 복합 protobuf 값은 현재 JSON으로 대체합니다.
열 이름을 키로 삼는 HTTP 행은 중복 열을 잃을 수 있고, JSON INT64 숫자는
클라이언트에서 정밀도를 잃을 수 있습니다. 오류 분류는 거칠고
`execute_with_params`는 매개변수 맵을 무시합니다. 이는 보완할 지점이며 완성된
에이전트용 보장이 아닙니다. `EXPLAIN`은 변경 미리보기가 아닌 쿼리 계획이며,
`PROFILE`은 문장을 실행합니다.

현재 `WHY`는 정수 ID를 사용하고 이력 조회는 명시 정점·간선의 `FETCH`에 한정됩니다.
과거 시점의 추론 폐쇄는 지원하지 않습니다. 추론에는 실행 한도가 있고, 복합 쓰기는
일반 트랜잭션이 아니며, `sameAs` 병합은 되돌릴 수 없습니다. 일부 온톨로지 기능이
OWL·SHACL·RDF·SPARQL·nGQL 전체 규격 준수를 뜻하지 않습니다.
기능 발견과 어댑터 문서에서도 이 경계를 유지합니다.

계약은 단계적으로 도입합니다. QRY-2 완전성 작업과 병행하여 AGT-1의 읽기 전용,
인가된 발견 스키마·픽스처부터 시작합니다. API-1/API-2와 EVAL-1을 1단계로 앞당기고
범위별 권한과 보안 배포를 2단계에 둡니다. 영속 쓰기 기반이 AGT-3/AGT-4를 가능하게
하며 근거 기능은 의미론적 선행 조건을 따릅니다. SDK와 AGT-5 어댑터 적합성은
핵심 계약 이후 4단계에 둡니다. 순서가 바뀌면 개발 플랜이 기준이며 새 전송 형식이
이를 우회해서는 안 됩니다.

## 에이전트 평가 — EVAL-1

모델·버전, 프롬프트, 도구 정의, 데이터셋·시드, 권한, 예산, 시도 횟수, 환경을
고정합니다. 비결정성을 기록하고 성공한 한 번을 고르는 대신 반복 결과를 보고합니다.
스키마 발견, 정확한 관계 조회, 설명, 삭제·추론 철회, 연결 종료 후 재시도,
동시 변경 충돌, 권한 거절, 한도·불완전한 결과 처리를 포함합니다.

최종 DB 상태와 답변의 근거를 정답 기준과 비교합니다. 무단 변경, 중복 쓰기,
오래된 결론, 지어낸 근거, 숨겨진 부분 결과를 실패로 셉니다. 그럴듯한 답변은
작업 성공이 아닙니다. 합성 또는 명시적으로 승인된 데이터를 쓰며 프롬프트,
추적, 저장한 결과, 공유 벤치마크 산출물의 자격 증명과 민감한 값을 가립니다.

정확성과 권한 검사를 통과한 뒤 호출 수, 입력·출력 토큰, 지연, 자원 사용을
비교합니다. 성공 작업 비용과 함께 실패 시도·재시도 비용도 보고합니다.
모델 비용, 어댑터 오버헤드, DB 실행 비용을 나눕니다. 그래프 DB는 동등한 어댑터와
동등한 작업 의미로 비교합니다. 워크플로 프레임워크는 저장소·오케스트레이션 조건을
같게 만들지 않는 한 별도 비교입니다. 어댑터의 이점을 저장 엔진의 이점으로
돌리거나 요구 수준이 다른 작업을 같은 것으로 비교하지 않습니다.

## 각 계약 구현 전에 결정할 사항

- 버전 정책과 정확한 전송 스키마: 손실 없는 정수·복합 값 포함.
- 인가된 발견 응답의 공개 정책과 첫 구조화 연산 집합.
- 데이터 뷰·리비전 단위, 커서 보존, 재시작 후 무효화.
- 원자적 변경 지원 범위, 멱등성 보존·할당량, 장애 복구.
- 미리보기 범위·영향 한도와 호출자의 영속 연산 식별 방법.
- 명시 사실·주장의 신뢰 정책과 지원하는 논리적 부재·부정 의미.
- 첫 도입자용 SDK, 프로토콜 어댑터 담당 범위, 대표 평가 작업.

해당 기능을 제공한다고 알리기 전에 담당 작업에서 결정합니다. 방향은 채택했지만
정확한 필드명, 보존 기간 값, 미완성 보장은 명시적인 완료 검사를 갖춘 설계 과제로
남아 있습니다.
